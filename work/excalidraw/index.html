Transcript

This is a client pitch for an open-source whiteboard app. Two features, built as working code, to get new visitors to save their first drawing.

Right now, the empty canvas tells a new visitor that their drawing lives in the browser, and that they should save it to a file. But the moment they start drawing, that message disappears, and nothing takes its place. Saving is tucked away in the main menu.

So our team of four built two features against one number: new visitors who save their first drawing. The first is a Save to file button that's always on screen.

The second is a one-time prompt. It waits for a real shape, fifteen seconds of visible time, and two seconds of stillness, so it never interrupts a stroke. Screen readers announce it, and it never steals focus.

Both of them open the same picker. The editable file is recommended, with PNG and SVG right beside it. Once you've saved, the prompt never comes back, but the button stays.

Every colour pair meets the accessibility contrast standard, in light mode and in dark. And if you open the picker from the keyboard and close it, focus goes right back to the button.

I made twenty-two of the twenty-seven commits on main, across six tagged releases. The test is sized at three thousand one hundred thirty-five users per arm, but it never ran on real traffic, so there's no result to claim.

01What it is

A client pitch built as working code inside Excalidraw itself: a one-time first-save prompt, and a persistent “Save to file” button with a format picker.

02How it works

Both arms of the experiment run in one live demo.

  • The demo switches between control and treatment arms from the URL, so a reviewer can see both without a build.
  • CI with CodeQL, a GitHub Pages demo, and every colour pair measured to WCAG AA.

03What it doesn't do

No result is claimed.

  • The test was sized at 3,135 users per arm, but it never ran on real traffic, so there is no KPI result to report.
